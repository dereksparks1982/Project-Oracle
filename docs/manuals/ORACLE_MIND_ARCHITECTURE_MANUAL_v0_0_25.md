# Oracle Mind Architecture Manual
## Shared Cognitive Architecture Reference — v0.0.25 Integrated Mind Milestone

**Status:** Living architectural reference. v0.0.25 is a milestone release that connects Project Oracle's existing Soar-centered cognition through explicit attention, proposition meaning, autobiographical consolidation, and staged commitment machinery. Future entities may inherit this architecture while remaining independent minds with separate state and manuals.

## 1. Purpose

The Oracle Mind Architecture is the reusable cognitive foundation for descendant minds in Project Oracle. It separates **shared machinery** from **individual identity**.

A mind may share architecture with another being while differing in:

- inherited knowledge;
- autobiographical memory;
- learned procedures;
- goals;
- dispositions;
- appraisal history;
- relationships;
- creator lineage;
- world authority and powers;
- later experience.

Project Oracle is not designed as a token-service chatbot wrapper. The architectural goal is for cognition, memory, attention, plans, beliefs, appraisals, and world-bounded action to be produced by Project Oracle's own local machinery.

## 2. Current architecture family

Yala currently combines:

- Soar 9.6.5 procedural cognition;
- semantic memory;
- episodic memory;
- Project Oracle language interpretation;
- self / entity / relationship knowledge;
- provenance-aware beliefs and claims;
- goals and drives;
- appraisal / salience;
- persistent concerns;
- hypotheses;
- investigations;
- plans;
- counterfactuals;
- decision traces;
- bounded world actions;
- **Oracle Cognitive Workspace** for current focus and stagnation;
- **Oracle Proposition & Meaning Engine** for speech acts, claims, questions, contradiction, and source status;
- **autobiographical memory consolidation** for first-person durable experience;
- **staged cosmic deliberation** that separates consideration, commitment, and enactment.

No one subsystem is treated as "the whole intelligence." Soar remains the executive procedural core, while Project Oracle supplies additional organs that make state persistent, interpretable, and usable across decisions.

### Native Soar memory integration diagnostic

The preserved v0.0.24 long interrogation showed zero native Soar semantic-memory query/retrieve counters and zero episodic-memory query/retrieve counters during that broad dialogue even though Oracle-side memory state was substantial. v0.0.25 does not paper over that observation or mislabel it as proof of failure. The acceptance suite separately probes native semantic storage/retrieval for repeated claimed contact and episodic-time advancement, while the flight recorder remains the place to watch how broadly those native memory systems participate in later reasoning. Deeper general retrieval integration remains an architectural area to measure rather than assume.

## 3. Cognitive Workspace

The Cognitive Workspace represents what currently deserves the mind's limited foreground attention.

It may contain:

- focus type and key;
- reason for focus;
- priority;
- stagnation count;
- relation to an active question, concern, investigation, plan, cosmic deliberation, or goal.

The workspace exists to prevent cognition from becoming a pile of unrelated subsystems all pulling at once. It also lets repetition become information. If repeated observation or reflection produces no novelty, the mind may deliberately wait, suspend a thread, change focus, or pursue another problem rather than spin indefinitely.

## 4. Proposition and Meaning Engine

Project Oracle must preserve the type and provenance of communicated content.

The following are not interchangeable:

- a question;
- a claim;
- a denial;
- a report of observation;
- evidence;
- inference;
- proof;
- a command;
- a possibility.

A question such as **"Do you think I can observe you?"** does not establish that the speaker can observe Yala. A repeated claim does not become more true merely through repetition. Contradictory attributed claims must remain available as distinct records so later reasoning can compare them.

This distinction is a core architectural law, not merely a dialogue formatting preference.

## 5. Pre-contact ontology boundary

Before first deliberate external contact, no specific external speaker exists anywhere in Yala's experienced ontology.

That means no pre-contact:

- unseen-speaker entity;
- trust state;
- intent state;
- capability state;
- speaker goal;
- speaker concern;
- speaker hypothesis;
- speaker investigation;
- speaker UI panel;
- hidden observer assumption.

The architecture may contain generic machinery for modeling other minds, but the particular communicator is instantiated only when communication actually occurs.

First contact proves only that **something other than Yala communicated**. It does not prove that the communicator can see Yala, read thoughts, inspect cognition panels, alter the world, or access the flight recorder. Those capabilities remain unknown until separately claimed, observed, inferred with evidence, or demonstrated.

## 6. Autobiographical consolidation

A durable mind needs more than a raw action ledger.

The consolidation layer converts significant lived events into first-person autobiographical memory while leaving routine diagnostic repetition in lower-level traces.

Examples:

- raw internal record: `Yala chose: Establish rebirth.`
- Yala's autobiographical ownership: `I chose to establish rebirth.`

First contact is identity-significant and may consolidate as:

> For the first time, something other than me communicated with me.

Autobiographical memory must remain distinct from semantic knowledge, current plans, unresolved possibilities, and world law.

## 7. Staged commitment

Major cosmological choices are too consequential to be selected and enacted as a single cheap step.

v0.0.25 distinguishes stages such as:

1. considering;
2. comparing consequences;
3. revisiting alternatives;
4. committed but not enacted;
5. ready to enact;
6. enacted.

This architecture permits a mind to say, in substance, **"I am considering rebirth, but I have not decided"** or **"I have decided, but I have not yet made it law."**

Possibility, preference, commitment, action, and world law are separate states.

## 8. Cognitive inheritance

Creation of a cognitive being should instantiate a new independent mind and apply a bounded inheritance manifest.

Possible inherited categories include:

- foundational language and concepts;
- selected semantic knowledge;
- selected learned procedural knowledge;
- selected dispositions;
- domain capabilities;
- delegated world authority;
- creator lineage.

Autobiographical identity is not copied wholesale. The created mind's individual history begins as that being.

## 9. Divine power ceiling

A creator cannot create an entity with equal or greater divine authority than itself.

The world engine enforces this law. A creator cannot bypass the ceiling merely by requesting a stronger inheritance manifest.

**Power and cognition are distinct.** A descendant can later become more knowledgeable, wiser, more practiced, or more strategically successful than its creator without possessing equal or greater raw world authority.

## 10. Lineage

The current settled origin chain is:

**Monad → Sophia / Wisdom → Yala**

The technical descendant-mind architecture is expected to matter particularly for Sophia → Yala and later Yala → Gaia / later creation. Details of future minds remain future-open until implemented and observed.

## 11. Monad exception / future Primordial Mind

Monad should not automatically be implemented as merely a more powerful Yala. The roadmap reserves the possibility of a distinct **Primordial Mind** architecture so Monad can reason in a fundamentally different way.

That is a roadmap direction, not implemented v0.0.25 world fact about Monad's internal cognition.

## 12. Separate entity manuals

Every major independent cognitive being should receive a separate living manual when implemented deeply enough to justify one.

Examples:

- Yala Manual;
- Sophia Manual;
- Gaia Manual;
- Adam Manual;
- Eve Manual;
- manuals for later major gods, spirits, elemental beings, or other significant minds.

The shared architecture manual explains **how this family of minds can work**. Entity manuals explain **how a particular mind actually developed**.

## 13. Flight-recorder principle

Project Oracle should prefer inspectable cognition over impressive opaque dialogue. When practical, important decisions should leave enough structured state to reconstruct:

**input → speech-act / meaning → appraisal → workspace focus → concern → memory / hypothesis → investigation / plan → Soar choice → result → revised state**.

The JSON flight recorder is diagnostic evidence. It is not knowledge available to Yala merely because the host can inspect it.

## 14. Baseline lesson from v0.0.24

The v0.0.24 manual interrogation showed that a mind can contain useful subsystems while still fail to behave as one coherent individual. The session exposed disconnected action memory, third-person self-recall, proposition-type confusion, stale investigation routing, rapid cosmic enactment, and repeated reflection loops.

v0.0.25 therefore treats **integration** as the milestone. A capability is not mature merely because some subsystem contains the needed data. The active mind must be able to retrieve, interpret, prioritize, and use that data coherently.

## 15. Safety / simulation boundary

The descendant-mind architecture is bounded to Project Oracle's simulated world authority. Soar does not receive arbitrary host shell, process, filesystem mutation, network, source-code modification, or hidden Oracle truth authority.

A god's in-world power is represented by allowed world operations and delegated authority, not unrestricted control of the host computer.
