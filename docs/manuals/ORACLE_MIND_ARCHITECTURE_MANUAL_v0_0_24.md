# Oracle Mind Architecture Manual
## Shared Cognitive Architecture Reference — v0.0.24

**Status:** Living architectural reference.  v0.0.24 primarily implements Yala.  Future entities may inherit from this architecture but must remain independent minds with separate state and manuals.

## 1. Purpose

The Oracle Mind Architecture is the reusable cognitive foundation for descendant minds in Project Oracle.  It separates **shared machinery** from **individual identity**.

A mind may share architecture with another being while differing in:

- inherited knowledge;
- autobiographical memory;
- learned procedures;
- goals;
- dispositions;
- appraisal history;
- relationships;
- creator lineage;
- world authority and powers;
- later experience.

## 2. Current architecture family

Yala currently combines:

- Soar 9.6.5 procedural cognition;
- semantic memory;
- episodic memory;
- Project Oracle language interpretation;
- self / entity / relationship knowledge;
- provenance-aware beliefs and claims;
- goals and drives;
- appraisal / salience;
- persistent concerns;
- hypotheses;
- investigations;
- plans;
- counterfactuals;
- decision traces;
- bounded world actions.

The architecture is intended to become reusable rather than leaving Yala as a one-off special case.

## 3. Cognitive inheritance

Creation of a cognitive being should instantiate a new independent mind and apply a bounded inheritance manifest.

Possible inherited categories include:

- foundational language and concepts;
- selected semantic knowledge;
- selected learned procedural knowledge;
- selected dispositions;
- domain capabilities;
- delegated world authority;
- creator lineage.

Autobiographical identity is not copied wholesale.  The created mind's individual history begins as that being.

## 4. Divine power ceiling

A creator cannot create an entity with equal or greater divine authority than itself.

The world engine enforces this law.  A creator cannot bypass the ceiling merely by requesting a stronger inheritance manifest.

**Power and cognition are distinct.** A descendant can later become more knowledgeable, wiser, more practiced, or more strategically successful than its creator without possessing equal or greater raw world authority.

## 5. Lineage

The current settled origin chain is:

**Monad → Sophia / Wisdom → Yala**

The technical descendant-mind architecture is expected to matter particularly for Sophia → Yala and later Yala → Gaia / later creation.  Details of future minds remain future-open until implemented and observed.

## 6. Monad exception / future Primordial Mind

Monad should not automatically be implemented as merely a more powerful Yala.  The roadmap reserves the possibility of a distinct **Primordial Mind** architecture so Monad can reason in a fundamentally different way.

That is a roadmap direction, not implemented v0.0.24 world fact about Monad's internal cognition.

## 7. Sophia as potential root descendant mind

Sophia / Wisdom created Yala, so Sophia is the natural candidate for the root or earlier form of the descendant-mind family.  When Sophia receives a brain, she may share substantial architecture with Yala while differing in state, experience, knowledge, power, dispositions, and interpretation of their relationship.

This remains an implementation direction until Sophia has an actual independent cognitive runtime.

## 8. Separate entity manuals

Every major independent cognitive being should receive a separate living manual when implemented deeply enough to justify one.

Examples:

- Yala Manual;
- Sophia Manual;
- Gaia Manual;
- Adam Manual;
- Eve Manual;
- manuals for later major gods, spirits, elemental beings, or other significant minds.

The shared architecture manual explains **how this family of minds can work**.  Entity manuals explain **how a particular mind actually developed**.

## 9. Flight-recorder principle

Project Oracle should prefer inspectable cognition over impressive opaque dialogue.  When practical, important decisions should leave enough structured state to reconstruct:

**input → appraisal → concern → memory / hypothesis → investigation / plan → Soar choice → result → revised state**.

The session JSON export is the primary v0.0.24 diagnostic surface for that purpose.

## 10. Safety / simulation boundary

The descendant-mind architecture is bounded to Project Oracle's simulated world authority.  Soar does not receive arbitrary host shell, process, filesystem mutation, network, source-code modification, or hidden Oracle truth authority.

A god's in-world power is represented by allowed world operations and delegated authority, not unrestricted control of the host computer.
