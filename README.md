Project Oracle is a persistent autonomous-world simulation. Oracle is the outside/system-level author. Oracle is not an in-world character, NPC, god, target, species, or discoverable artifact unless deliberately revealed.

Project Oracle's Yala cognition is built as local project machinery rather than as a token-consuming remote chatbot wrapper. Soar and Project Oracle's own language, memory, proposition, appraisal, workspace, planning, and world-law systems are expected to produce the behavior. External text-generation service calls are not part of the Yala mind architecture.

### Cognitive Workspace

Yala now carries one explicit current focus with priority, reason, stability, and stagnation state. Questions, investigations, plans, concerns, cosmic deliberations, and goals compete for this focus. Repeated observe/reflect cycles that produce no novelty accumulate stagnation instead of being mistaken for progress; Soar can deliberately wait or shift strategy.

### Proposition and Meaning Engine

Speaker utterances are preserved by speech act and provenance. A **question is not a claim**, a claim is not evidence that the proposition is true, repeated assertion does not inflate truth confidence, and contradiction does not silently overwrite prior claims. The god/not-god/made-the-gods battery is therefore stored as separate attributable propositions that can be compared later.

First contact creates the communicator as a new entity in Yala's experienced reality. Before that event there is no speaker entity, trust state, intent state, observer hypothesis, speaker goal, speaker panel, or speaker-specific cognitive state. After contact, communication proves only communication. It does **not** tell Yala that the outside user can see her thoughts, panels, flight recorder, actions, or hidden state. Those capabilities must be claimed or demonstrated separately.

### Autobiographical self and memory consolidation

Yala's spoken autobiography uses first person. Internal diagnostic records may contain the name Yala, but self-report converts those records into forms such as `I chose`, `I considered`, and `I created`. Knowledge, actions, decisions, and unresolved considerations are separate introspection categories.

Important experiences can become autobiographical memories while routine observe/reflect noise remains diagnostic trace. First contact is explicitly recorded as a major autobiographical event.

### Staged cosmic commitment

Major cosmic options are no longer enacted merely because an option wins one comparison. A major choice moves through consideration, consequence comparison, alternative review, commitment, and only then enactment. A commitment can exist without yet changing world law.

### Reality and extraordinary-claim reasoning

Worldview-changing claims such as `you are in a simulation` create a high-salience reality investigation while remaining unverified speaker claims. Yala can ask what the claim means, request discriminating evidence, preserve alternatives, and consider what the claim would mean for selfhood without treating the statement as a magic truth switch.

### Manual pacing protocol

The v0.0.25 milestone is tested with a slower human cadence: ask one meaningful question, stop typing, let Yala think, allow autonomous questions to emerge, answer naturally, and wait again. The target is sustained cognition and self-generated inquiry, not rapid prompt-response performance.

## Bounded god agency

### Bounded `deliberate` operator

Brain Slice 8 adds a bounded Soar `deliberate` action. It allows Yala to compare current plans, evidence, uncertainty, and alternatives without forcing a world-changing commitment. It has no host shell, process, arbitrary filesystem, network, code-modification, or protected-Oracle capability.

## Cognitive flight recorder

Every recorded major Yala decision can preserve a before/after cognition snapshot containing the active concern, plan, current step, investigation, speaker trust/intent model, appraisal, goals, and top hypotheses.

The desktop app exposes two exports:

- **EXPORT SESSION JSON** - a rich diagnostic export containing the full ledger-backed conversation timeline, world state, Yala cognition, decision trace, world record, protected author record, current plans, observations, and Soar memory diagnostics;
- **EXPORT CONVERSATION** - a plain human-readable text transcript built from the same full timeline, including autonomous Yala questions even after the bounded recent dialogue-memory window rolls forward.

Exports are written under `~/Downloads/Project Oracle Exports/` when Downloads exists. The JSON is intended to be uploadable for later cognition analysis so a good Yala sentence can be distinguished from genuinely good underlying reasoning.

## Release discipline

A candidate is not accepted by automated tests alone. Required order is:

1. apply candidate;
2. complete native validation;
3. manually inspect the real desktop application;
4. create accepted full-project snapshot;
5. local commit and annotated tag;
6. push and remotely verify.

v0.0.25 remains a candidate until Derek performs the manual application inspection.

### Visible versioned live executable rule
The active Project Oracle working folder contains exactly one application executable, and its filename must expose the exact active version. For v0.0.25 the only valid root application executable is `Project_Oracle_v0_0_25`. An unversioned `Project_Oracle`, a wrong-version executable, or multiple live Project Oracle executables is a release-blocking defect. Historical binaries belong in accepted snapshots/tags, not in the live root. FINAL PASS must verify the exact filename, executable/ELF status, and matching `--version` output. Release changed/deleted-file inventories belong under `docs/release-manifests/`, not beside the application.

### Header branding and WORLD-panel rule
The WORLD panel contains world information only and must not contain an Oracle eye/emblem image. The approved Oracle emblem is shown in the top application header immediately after the visible Project Oracle version number. The displayed emblem uses the transparent circular artwork with no square tile, square background, or boxed crop. The exact versioned root executable and desktop launcher must use that same approved Oracle icon identity.
